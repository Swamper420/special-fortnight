## 1. Frame base and ESP accounting (`ev_cda7...`, verbatim)

Prologue (`0x434390-0x4343ab`): three pushes + `SUB ESP,0x44` + four
pushes = `0x60` bytes below the return address. Define `B` = ESP after
the prologue. Param slots: `param_k = [B+0x64+4(k-1)]`
(`param_1=[B+0x64] … param_15=[B+0x9c]`).

Anchor section (`0x4344e1/0x4344ed`): two `PUSH EBP` (EBP=0,
`0x4343bc`) shift ESP to `B-8` before any anchor store; those two
words become the b60 `dda60(0,0)` args (`0x4345fd`, callee `RET 8`
restores ESP to `B`). So during anchors `param_k=[ESP+0x6c+4(k-1)]`
(ESP=`B-8`); after `0x4345fd`, ESP=`B` and `param_k=[ESP+0x64+4(k-1)]`
for the rest of the function. Every emit call below is callee-cleaned
(`dda60/ddae0` `RET 8`, `ddcb0/ddf10` `RET 0x10`, `443060` `RET 0x18`,
`dd970` no args), so ESP returns to `B` after each — cross-checked by
§3: every post-call slot read lands on its predicted anchor/param,
and a 4-byte imbalance anywhere would shift all later reads.

Convention at every site (observation): pushed-last = `param_1`
(stdcall, mirrors the inrun `ddf10` site). Several sites push a
garbage `ECX` first purely to reserve the slot, then overwrite it via
`FSTP [ESP]` / `MOV` (§3). Mid-push slot reads (ESP already moved by
earlier pushes at the same site) occur at `ddf10#1`, `ddcb0#2`, and
`ddae0`-b68-`#3` — each resolved below by absolute `B+off`, not by
decompiler trust.
