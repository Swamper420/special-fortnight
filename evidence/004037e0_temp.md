## 1. Claim

`FUN_004037e0` is a Borland-style wide-string substring-assign op.
Calling convention (observed): `ECX` = dest string object, 3 stack
params = (src object, start index, max count); returns dest in
`EAX`; `RET 0xc`. At the f3e0 loop site it runs as
`037e0(temp1, key, 0, -1)` — a full-key copy (or alias, see §4)
into temp1. The caller pre-seed byte (`AL=[EDI]` at dest+0) is
never read by this body; dest fields used are `+0x4/+0x8/+0xC`
only. Which compare slot each temp lands in (BST U1 remainder)
is NOT closed here — that needs the `0x55f460` ESP-slot mapping
plus temp2's builder.

## 3. Temp layout at the f3e0 call site (observed)

From the f3e0 loop dossier (`ev_4d70...`,
`0x55f419-0x55f438`):

```
SUB ESP,0x10        ; temp1: 16 B at ESP
MOV ECX,ESP         ; dest = ESP
MOV [ESP+0x38],ESP  ; temp1 self-ref into later compare arg area
[ECX+0x0] = AL      ; AL = [EDI] = key first byte (1 byte store)
[ECX+0x4] = 0       ; dest ptr  = empty init
[ECX+0x8] = 0       ; dest len  = empty init
[ECX+0xC] = 0       ; dest 3rd word = empty init
PUSH [0x5cd2ec]     ; param_3 = 0xFFFFFFFF (obs. §2 bytes)
PUSH 0              ; param_2 = 0 (EBX zeroed at 0x55f414)
PUSH EDI            ; param_1 = key object
CALL 004037e0       ; RET 0xC
```

So dest object base = `ESP`, 16 B: `+0x0` seed byte (caller-set),
`+0x4` buffer ptr, `+0x8` length (wide chars), `+0xC` third word
(capacity or equivalent — Borland string header shape inferred,
see U2). Temp2 by contrast is 12 B (`SUB ESP,0xc`, no pre-seed)
built by `00405550` (1 stack param). The `+0x0` seed survives
this call untouched (observation: no `in_ECX+0` read in body).
