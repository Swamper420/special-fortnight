## 1. Claim

`FUN_00405550` is a single-source Borland-style wide-string copy op.
Calling convention (observed): `ECX` = dest string object, 1 stack
param = src object; returns dest in `EAX`; `RET 0x4`. The length
clamp comes from the global dword `[0x5cd2ec]`, not from a stack
param (this is the structural difference vs `004037e0`). At the f3e0
loop site it runs as `05550(temp2, node+0xC)` — a full
candidate-string copy (or alias, runtime data) into temp2.

Arg-order closure (inference from observed insns, balance-verified
in §5): at `0x55f460` the 8 `RET 0x20` compare args ARE the two
temp objects laid end-to-end (`[T2][T1]`). First string
(`[ESP+0x24]` ptr / `[ESP+0x28]` len, callee frame) = temp2 =
candidate; second string (`[ESP+0x34]` ptr / `[ESP+0x38]` len) =
temp1 = key. So `AL = (candidate < key)`. Tree direction follows:
`AL!=0` (candidate<key) descends `[ESI+0x8]` with no record;
`AL==0` (candidate>=key) records the node and descends
`[ESI+0x0]`. Equal keys take the record-then-`+0x0` side. This
closes the BST U1 remainder named in `evidence/004037e0_temp.md`
(U1) and `evidence/0055f3e0_bst.md` (U1).

## 2. Signature / inputs (observed)

- `ECX` = dest (`MOV ESI,ECX` at `0x405559`; `ESI` is the dest
  base; all 3 exits return `EAX=ESI`).
- One stack param (`MOV EBX,[ESP+0x8]` at `0x405551` → src
  object; 3 exits all `RET 0x4`: `0x4055de` self path,
  `0x40562d` alias path, `0x405666` general path).
- Src fields read: `[EBX+0x0]` seed byte, `[EBX+0x4]` buffer ptr,
  `[EBX+0x8]` length (`0x405557/0x405569/0x4055e9...`).
- Length clamp (observed): `EDI = min(src_len, [0x5cd2ec])`
  (`0x40556c-0x405577`; decompiler flags the fallthrough block
  `0x405577` unreachable-removed, behavior unchanged). Given the
  observed global value `0xFFFFFFFF` (dossier `ev_9f50...` in
  `004037e0_temp.md`), the clamp is currently a no-op; the
  `min()` shape is what is transcribed, not the no-op.
- Ghidra native_api (`ev_3c8c...`): `__stdcall`, `void` return,
  1 param `undefined1 *`, confidence low, source default — the
  register `ECX` dest makes it effectively thiscall; treat the
  convention label as untrusted (same caveat as `004037e0`).

## 3. Temp2 layout at the f3e0 call site (observed)

From the loop dossier (`ev_4d70...`, `0x55f447-0x55f451`):

```
SUB ESP,0xc            ; temp2: 12 B at ESP (= T2)
MOV ECX,ESP            ; dest = T2
MOV [ESP+0x34],ESP     ; T2 self-ref store (outside later arg block, see §5/U1)
PUSH EAX               ; src = node+0xC object (EAX from 00407650)
CALL 00405550          ; RET 0x4 (consumes pushed arg)
```

`00407650` (`ev_fd27...`) is exactly
`MOV EAX,[ESP+0x4]; ADD EAX,0xC; RET` (8 B, plain `RET`, so the
`PUSH ESI` candidate node at `0x55f43d` stays on the stack).
Dest object spans 16 B (`+0x0` seed byte from `[src+0]`,
`+0x4` buffer ptr, `+0x8` len, `+0xC` third word — all written by
the body at `0x40555e-0x405566` and later paths), i.e. 4 bytes
past the 12 B `SUB`. Those 4 bytes (`[T2+0xC]`) land on the stale
`PUSH ESI` slot (`ESP1-4`, notation in §5), whose value was
already consumed by `00407650` — observed overlap, no conflict.
Unlike temp1, temp2 has no caller pre-seed: its `+0x0` comes
straight from the src object (`*in_ECX = *param_1`).

## 4. What it copies/transforms (observed pseudocode, `ev_3c8c...`)

```c
void FUN_00405550(undefined1 *param_1)
// in_ECX = dest; returns dest (EAX = in_ECX at every exit)
{
  *in_ECX = *param_1;            // seed byte
  *(in_ECX+4) = *(in_ECX+8) = *(in_ECX+0xc) = 0;   // empty init
  EDI = min(*(param_1+8), [0x5cd2ec]);
  if (in_ECX == param_1) {
    // self path (NOT taken at f3e0): error if EDI!=0 via
    // 0059c277, normalize via 00403a50, memmove via 004039f0,
    // truncate checks via 00402d50/00402d30
    ...
    return;
  }
  if ((EDI != 0) && (EDI == *(param_1+8))) {
    // full-length alias fast path (0x4055e1-0x40562d):
    // null src ptr falls back to &DAT_005cd2e8; share-and-inc
    // iff refcount byte at [ptr-1] < 0xFE, else general path
    *(in_ECX+4) = src_ptr; *(in_ECX+8) = src_len;
    *(in_ECX+0xc) = *(param_1+0xc);
    (*(char *)(src_ptr-1))++;
    return;
  }
  // general path (0x405630-0x405666): capacity via 00402d50,
  // word copy via 00402920, finalize via 00402d30
  ...
  return;
}
```

(Full decompiler text in dossier `ev_3c8c...`; callee role
labels are positional inference, none analyzed.) At f3e0 the
self path is not taken (dest `T2` != src `node+0xC`); temp2 ends
up holding the full candidate string by either the alias or the
copy path — decided at runtime by the refcount byte at
`[cand_ptr-1]`, same as temp1. Copy vs alias is indistinguishable
to the compare; it matters only for lifetime/ownership
reconstruction (carried unknown, ex-temp-U1).

Assembly key ranges (`ev_2861...`): entry/prologue
`0x405550-0x405579` (param decode, clamp); self path
`0x405579-0x4055de`; alias path `0x4055e1-0x40562d`
(refcount-byte tests `0x4055f5`, share-and-inc
`0x405610-0x405628`); general path `0x405630-0x405666`.

## 5. ESP-slot mapping at `0x55f460` (arg-order proof)

Stack accounting from observed insns (`ev_4d70...`), `ESP0` =
loop-top ESP, `ESP1` = post-`SUB ESP,0x10` (temp1 base `T1`):

| step | insns | ESP after |
|---|---|---|
| temp1 alloc | `0x55f41b SUB ESP,0x10` | `ESP1 = ESP0-16` (`T1` = `ESP1..ESP1+15`) |
| temp1 build | `PUSH,PUSH,PUSH + CALL 004037e0` (`RET 0xC`) | `ESP1` |
| stale push | `0x55f43d PUSH ESI` (consumed in place by plain-`RET` `00407650`) | `ESP1-4` |
| temp2 alloc | `0x55f447 SUB ESP,0xC` | `ESP3 = ESP1-16` (`T2` base = `ESP3`) |
| temp2 build | `PUSH EAX + CALL 00405550` (`RET 0x4`) | `ESP3` |
| compare call | `0x55f460 CALL 00419820` (`RET 0x20`) | `ESP3+32 = ESP1+16 = ESP0` |

Balance check (observation): `RET 0x20` pops exactly the 32 B
below `ESP1` (16 temp1 + 4 stale push + 12 temp2), restoring
`ESP0` for the next iteration — so the 32 B block
`[ESP3..ESP3+31]` IS the 8-dword arg payload, passed by overlap,
not by extra pushes (there are none between `0x55f451` and
`0x55f460`).

Callee frame (`ev_2378...`): 7 pushes (SEH ×3 + saved regs ×4) =
28 B; return address at `[ESP+28]`; caller arg `i` at callee
`[ESP+32+4i]`. Observed string-slot reads:

| callee slot | caller arg `i` | block content (T2/T1 field offsets from §3 + `004037e0_temp.md` §3) |
|---|---|---|
| `[ESP+0x24]` first ptr (`ESI`, word-walked, `[ESI-1]` refcount) | `i=1` | `T2+4` = candidate buffer ptr |
| `[ESP+0x28]` first len (`EDI`, min/tiebreak) | `i=2` | `T2+8` = candidate len |
| `[ESP+0x34]` second ptr (`EBP`, or default `0x5cd2e8` when null) | `i=5` | `T1+4` = key buffer ptr |
| `[ESP+0x38]` second len (`EBX`) | `i=6` | `T1+8` = key len |

Remaining dwords are padding the body never reads (decompiler
param def-use in `ev_45ec...` shows uses only for ordinals
1,2,5,6 = first ptr/len, second ptr/len): `i=0` = `T2+0` seed
word, `i=3` = `T2+0xC` third word, `i=4` = `T1+0` seed word,
`i=7` = `T1+0xC` third word. I.e. the payload is literally the
two 16 B temp objects `[T2][T1]` back to back.

Result: first compare string = temp2 (candidate), second =
temp1 (key); `AL = (candidate < key)` (predicate settled in
`0055f3e0_bst.md` §4 via `SETL`). Direction: `AL!=0`
(candidate<key) → `[ESI+0x8]` child, no record; `AL==0`
(candidate>=key) → record node, `[ESI+0x0]` child. Equal keys
record and go `+0x0`. So `+0x8` is the lesser side, `+0x0` the
greater-or-equal side. By the §3 temp-source swap (key/candidate
roles exchanged at the `0055e910` slow path), the slow-path
predicate direction is the mirror — verifying that site is the
follow-up, not part of this claim.

## Unknowns

- U1 (open, non-load-bearing for direction): purpose of the
  three outside-block stores — `[ESP1+0x38]=T1` (`0x55f420`),
  `[ESP1-4+0x34]=0` (`0x55f43e`, later overwritten by
  `[ESP3+0x40]=-1` at `0x55f458`), `[ESP3+0x34]=T2`
  (`0x55f44c`). All sit above the 32 B arg block (offsets
  `0x34/0x38/0x40` vs block depth), so they are frame locals of
  some kind, not compare args; consumer unexamined.
- U2 (open, carried from `004037e0_temp.md` U2): `+0xC` third-word
  meaning; `+0x0` seed-byte consumer — the compare never reads
  args `i=0/i=4` (no def-use in `ev_45ec...`), and neither
  builder reads dest `+0x0` after writing it, so the seed's
  reader is still unidentified.
- U3 (open): callee roles (`00402920` copy, `00403a50`
  normalize, `0059c277` error, etc.) positional inference, none
  analyzed; alias-vs-copy ownership at runtime (refcount byte)
  same gap as temp1 — compare semantics unaffected either way.
- U4 (open): 8th arg dword (`i=7` = `T1+0xC`) has no named
  decompiler param and no observed reader; treated as padding.
  If a future dossier shows a reader, §5 slot table needs
  revision — but first/second string slots used by the predicate
  are fixed by direct insn observation.
