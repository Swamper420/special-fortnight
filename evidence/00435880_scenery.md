## 1. Claim

`FUN_00435880` handles the hill-XML `stairs` section. It allocates one
`0x58`-byte node, constructs it (`FUN_00436050`), stores its 4 parsed
floats at node `+0x0/+0x4/+0x8/+0xc` (`FUN_00436020`), and appends the
node to the hill-object vector at `+0x218` (via `FUN_00437df0`,
insert position `*(hill+0x220)`). It returns the node pointer, or
null if allocation failed. No model refs, no placements, no float
math of its own — only allocation, one 4-word store, one vector
append, and a refcounted shared-pointer wrapper.

Only proven-pure fragment transcribed to Rust: `FUN_00436050`-style
zeroing is NOT proven (calls `FUN_00435cc0` twice, unexamined);
