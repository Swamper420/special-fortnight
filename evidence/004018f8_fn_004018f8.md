## Verification

- Assembly comparison: Rust in `src/fn_004018f8.rs` keeps the exact
  top-level dispatch predicates in order (`> 0xa2c`, `> 0x40a2c`,
  signed `< 0 → null`), the wrapping size-class math
  (`(p+0x10013)&0xffff0000`, `(p+0xd3)&~0xff +0x30`,
  `(p+3)>>3`), and delegates heap-state region bodies to hooks.
- Unit test: single sequential test covers small-lane routing+index
  math, bucket rounding math, huge-lane reserve math, negative → null,
  and hook passthrough. Verified: `cargo test` 110 pass,
  `cargo build --target i686-pc-windows-gnu` clean (integrated batch).
- Note: bucket worked example `0xa2d → rounded 0xb00, total 0xb30`
  (`(p+0xd3)&~0xff`); an earlier test revision had `0xa00/0xa30`.

## Unknowns:

- Observation: the body contains no `VirtualAlloc`/`VirtualFree`
  import call; the dossier's inline `VirtualAlloc` paragraph has no
  corresponding `CALL` in the observed assembly — the huge lane ends
  `POP EBX; TEST EAX,EAX; JNS 0x4016a4; XOR EAX,EAX; RET`, i.e. a
  tail continuation into `FUN_004016a4` for non-negative sizes.
  Inference: the inline-`VirtualAlloc` pseudocode is a cross-function
  decompiler artifact for the `0x4016a4` continuation. Rust models the
  whole huge lane as `HOOK_LARGE_ALLOC`; binding `0x4016a4`'s real
  behavior is unproven.
- Observation: small-lane tables `DAT_004138dc` (byte class per
  `(p+3)>>3`), `DAT_0041205c` (8-byte descriptors), bitmaps
  `DAT_00413a40/44`, freelists `DAT_00413ac4/c8`, locks
  `DAT_0041304d/004138d5/00413a34`, top-chunk `DAT_00413a38/3c` are
  read/written throughout the region bodies; their extents and init
  state are unproven on host. Rust passes only `(index, param)` /
  `(rounded, total)` across the hook boundary.
- Inference: `param_1` is a byte size; header tags written are
  `rounded+0x32` (bucket) / `uVar+6` (small), both with low flag bits;
  exact flag semantics unproven beyond observed constants.
- Unknown: whether callers pass sizes that can make
  `param_1+0xd3`/`+0x10013` wrap (Rust uses `wrapping_add` to match
  x86 wrap); semantic name unproven; kept as `fn_004018f8`.
