## 1. Observation: wrapper `0x59e3a0-0x59e3b8`

```text
0x59e3a0: SUB ESP,0x10
0x59e3a3: FXCH
0x59e3a5: FSTP double ptr [ESP]       ; base = (double)ST1-entry
0x59e3a8: FST  double ptr [ESP+0x8]   ; exp  = (double)ST0-entry
0x59e3ac: MOV EAX,[ESP+0xc]           ; exp high dword (classify fast path)
0x59e3b0: CALL 0x0059e3c2
0x59e3b5: ADD ESP,0x10
0x59e3b8: RET
```

x87 two-double calling convention: entry `ST0` = exp, `ST1` = base
(slot+8 pushes `1+d1^2` first, `1.5` second, so at its `CALL 0x59e3a0`
`ST0 = 1.5`, `ST1 = 1+d1^2`). Stack doubles `[ESP] = base`,
`[ESP+8] = exp`; `EAX` = exp high dword. Returns double in `ST0`.
No branch, no strings, sole callee `0059e3c2`.

## 2. Observation: core `0x59e3c2-0x59e594` is CRT `pow`

Signature (behavioral, from asm + decompiler): 
`double FUN_0059e3c2(double base /*[ESP+8]*/, double exp /*[ESP+16]*/)`.
CRT `pow` traits, each observed:

1. **Log/exp reconstruction**: `FYL2X` at `0x59e40f` (`y*log2(x)`), then
   `CALL 0x005a3740` = `2^x` via `F2XM1`/`FSCALE` (`ev_8eb95307...`).
   Classical `pow = 2^(y*log2(x))`.

   extended-double consts `[0x618a10]`/`[0x618a70]`) vs 0 ("run main

## 3. Behavior map for slot+8's reachable inputs

Slot+8 calls `pow(1+d1^2, 1.5)` where `d1` is the f32 slope:

- Finite `d1` → base `1+d1^2 >= 1 > 0`: never EDOM. Main
  `FYL2X`→`exp2` path. Rust `f64::powf` matches to ≤1 ulp
  (x87 uses 80-bit intermediates; recorded as caveat, same class as
  the `atan`/`ST0` caveats in `fn_004de480.rs`/`fn_004432c0.rs`).
- `d1 = ±Inf` → base `+Inf` → `+Inf` both sides (observation: base-Inf
  arm; inference: positive-Inf result for `exp = 1.5 > 0`).
- `d1 = NaN` → base `NaN` → `NaN` both sides (`powf(NaN, 1.5)` is NaN;
  helper NaN arm returns NaN — full NaN-payload matrix unverified,
  payload bits unclaimed).
- `FST m32 [ESP+4]` at `0x44332c` (f32 round of `1+d1^2`) has no
  consumer: the base travels `ST0`→`FSTP double [ESP]` (80-bit→64-bit
  direct). Transcription computes the base in `f64` from the f32 `d1`
  (`1.0 + (d1 as f64)^2`), which is the closest one-line match
  (avoids a spurious f32 rounding the asm never takes).
- `d2` (`y''`) is recomputed from scratch at `0x44333b-0x44334e`
  (same formula, no side effects); transcription computes it once —
  bit-identical value, noted here so nobody "fixes" it back.
